## 3.2 仿真软件开发

本章所介绍的仿真系统——绳驱折纸灵巧手数值仿真与验证平台（Synergy Hand Simulator）——是一个面向绳驱折纸结构的从设计到仿真验证的完整软件框架。该平台采用模块化架构，集成了交互式计算机辅助设计（CAD）、运动学与传动建模、多体动力学仿真以及协同驱动算法验证等核心功能。软件的总体架构如图 3.1 所示。本节将按照数据流向，自底向上介绍各核心模块的设计与实现。

### 3.2.1 项目整体架构与工作流

本仿真平台采用 Python 语言开发，基于对象化的模块设计，主要依赖 NumPy 进行矩阵运算、PyQt5 构建图形用户界面、MuJoCo 物理引擎进行交互式仿真验证。项目目录结构如图 3.1 所示，核心模块包括：

- **折纸计算机辅助设计模块（`src/origami_cad/`）**：基于 PyQt5 的交互式二维 CAD 系统，用于绘制和编辑折纸手的展开图，包括折痕线、滑轮、孔、阻尼器、驱动器及腱绳路径等元件的可视化设计。
- **模型构建模块（`src/models/`）**：包含折纸设计的数据结构定义（`origami_design.py`）、DXF 文件的解析与拓扑重建（`origami_parser.py`）、折痕运动学计算（`origami_kinematics.py`）、URDF/STL 文件的自动导出（`origami_to_urdf.py`），以及缆绳传动矩阵的构建（`transmission_builder.py`、`hole_transmission.py`）。
- **协同驱动算法模块（`src/synergy/`）**：实现了从基本自适应协同（`base_adaptive.py`）到增强自适应协同（`augmented_adaptive.py`）再到动态协同（`dynamic_synergy.py`）的完整算法谱系，以及摩擦效应分析工具（`friction_analysis.py`）。
- **交互式仿真模块（`src/interactive/`）**：封装了 MuJoCo 物理引擎（`mujoco_simulator.py`）、Pinocchio 运动学求解器（`pinocchio_simulator.py`）以及自定义的折纸运动学仿真器（`origami_simulator.py`）。
- **数值仿真模块（`src/simulation/`）**：实现了完整的摩擦-阻尼物理模型（`friction_models.py`、`contact_model.py`）、准静态和动力学求解器（`quasi_static.py`、`dynamics.py`、`integrator.py`）、以及缆绳张力计算（`transmission_force.py`）。

典型的工作流为：用户首先通过 CAD 模块绘制折纸手的二维展开图，保存为自定义的 `.ohd` 格式文件；然后调用拓扑重建算法自动识别面片和关节连接，构建运动学模型；接着通过模型构建模块计算传动矩阵和协同矩阵，并将设计导出为 URDF 格式的机器人描述文件及 STL 格式的三维网格文件；最后，系统自动加载 URDF 模型进入 MuJoCo 仿真环境，用户可以通过滑块交互式地调节驱动输入，实时观察手指的运动学响应并可切换不同的协同模型进行对比验证。

### 3.2.2 交互式折纸 CAD 系统

**设计背景与用户交互。** CAD 模块是仿真平台的入口和核心交互界面。传统的折纸灵巧手设计流程通常依赖于工绘制展开图后手工计算几何参数，步骤繁琐且容易出错。本平台开发的可视化 CAD 系统允许用户在图形界面中直接绘制、编辑和保存折纸手的二维设计图，所见即所得。系统基于 PyQt5 的 QGraphicsView/ QGraphicsScene 框架实现，主要交互功能包括：

（1）**多模式绘图工具栏**。用户可通过工具栏或快捷键（L/M/V 分别对应轮廓线/峰折线/谷折线）切换绘图模式，在场景中点击或通过浮动坐标输入框精确绘制折痕线段。系统支持端点自动吸附（snap）功能，确保线段端点精确对齐。

（2）**图元放置与编辑**。支持在折痕线上放置滑轮（灰色圆，快捷键 P）、在折痕线附近放置孔（橙色圆，快捷键 H）和阻尼器（浅绿色圆，快捷键 D），以及放置驱动器（蓝色/红色圆对应 Motor A/B，快捷键 A）。所有图元均支持点击选中后通过右侧属性面板编辑参数，包括折痕线的刚度系数、滑轮的半径和摩擦系数、孔的板厚偏移和摩擦系数、阻尼器的阻尼系数等。

（3）**腱绳路径绘制**。用户按下 T 键进入腱绳绘制模式后，依次点击设计中的滑轮、孔、阻尼器和驱动器，系统自动在相邻节点间绘制紫色连线表示腱绳路径。绘制完成后，系统自动对路径中的孔和阻尼器进行后处理：对相邻孔对，识别它们穿过的折痕线并自动设置孔的关联折痕 ID；对同一路径中的阻尼器，收集路径中所有孔关联的折痕，将这些折痕关联到阻尼器（一个阻尼器可以同时关联多个折痕，例如在 SoftHand Pro-D 中一个阻尼器同时连接近端和远端关节）。右击或按 Esc 键完成腱绳绘制。

（4）**文件操作**。设计可通过文件菜单保存为自定义的 `.ohd` 格式（基于 JSON 的序列化格式），支持后续打开编辑。同时支持导出为标准 DXF 格式文件以兼容其他 CAD 软件。

（5）**视图操作**。支持鼠标滚轮缩放（缩放比例在视图左上角实时显示）、中键拖拽平移画布、以及 Y 轴翻转（向上为正，符合折纸设计习惯）。

### 3.2.3 OHD 数据结构的定义

OHD（Origami Hand Design）格式是本平台自定义的折纸手设计数据存储格式，采用 JSON 序列化，具有自描述、易解析、跨平台的特点。该数据结构的核心类是 `OrigamiHandDesign`（定义于 `src/models/origami_design.py`），主要包含以下数据字段：

- **几何元素**：折痕线（`FoldLine`）记录起点、终点坐标和折痕类型（轮廓线 OUTLINE、峰折 MOUNTAIN、谷折 VALLEY）和刚度系数；面片（`OrigamiFace`）记录顶点序列和关联的边 ID 列表。
- **传动元件**：滑轮（`Pulley`）记录位置、半径和摩擦系数，可关联一条折痕线；孔（`Hole`）记录位置、板厚偏移量、摩擦系数和关联折痕；阻尼器（`Damper`）记录位置、关联折痕列表和对应的传动比列表、阻尼系数。
- **腱绳路径**：腱绳（`Tendon`）以整数序列 `pulley_sequence` 记录路径中传动元素的遍历顺序，滑轮使用非负 ID，驱动器使用 -1（Motor A）/ -2（Motor B），孔使用 ≤ -100 的负整数，阻尼器使用 ≤ -200 的负整数。依赖 `is_hole_id()`、`is_damper_id()` 等辅助函数进行类型识别。
- **驱动配置**：驱动器（`Actuator`）记录名称和位移值，以及驱动器在场景中的位置坐标（`actuator_positions`）。

该数据结构的设计充分考虑了折纸手拓扑的复杂性。`build_topology()` 方法实现了从折痕线集合到面片和关节连接的自动重建：首先在折痕线交点处分割线段，确保图为严格平面图；然后建立无向图并采用最小环路（minimal cycle）算法遍历找到所有面片；再通过面积过滤去除碎片面；最后根据边-面邻接关系建立关节连接和面片树状层次结构。重建完成后，该方法还会按几何最近原则自动修复孔和滑轮的关联折痕 ID。

### 3.2.4 DXF 文件的解析与拓扑重建

为兼容现有的 CAD 设计流程，系统支持从标准 DXF 格式文件导入折纸手设计。DXF 解析器（`OrigamiParser`，定义于 `src/models/origami_parser.py`）的核心解析流程如下：

（1）**线段提取**。从 DXF 的模型空间（modelspace）中读取所有 LINE 和 LWPOLYLINE 实体，根据 DXF 颜色索引映射折痕类型：红色（索引 1）识别为峰折、蓝色（索引 5）识别为谷折、黑色（索引 7）识别为轮廓线。

（2）**线段分割**。在提取的所有线段交点处进行分割操作，确保图中不存在交叉线段，每条线段仅连接两个顶点。这是后续拓扑重建的前提条件。

（3）**图构建与最小面查找**。将分割后的顶点和边构建为无向图，对每个顶点的邻接边按方位角排序，然后通过"最小右转"算法沿边界的逆时针方向遍历所有最小环路（minimal cycle），这一算法的正确性依赖于平面图的性质——在平面图中，每个最小环路对应一个面片。

（4）**外轮廓去除与碎片过滤**。计算所有面片的有向面积，删除面积最大的外轮廓面（面积比通常 > 1.5 倍），同时过滤面积小于最大面积 1% 的碎片面。剩余的即为折纸手的实际面片。

（5）**关节连接建立**。基于边-面邻接关系：若一条折痕线两侧恰好有两个面片，则在这两个面片之间建立一个关节连接（`JointConnection`），关节类型继承折痕线的类型（峰折/谷折）。

### 3.2.5 URDF 文件的自动导出

为了实现从二维设计到三维仿真的自动转换，系统实现了 URDF 和 STL 文件的自动导出功能（`export_urdf()`，定义于 `src/models/origami_to_urdf.py`）。导出过程包含三个关键步骤：

（1）**面片定位策略**。系统采用"折痕对齐法"确定每个面片（link）在三维空间中的位置。根面片的上表面位于世界坐标系 $z=0$ 平面；对于谷折连接，子面片的关节轴位于父面片上表面，子面片原点也在同一高度；对于峰折连接，子面片的关节轴位于父面片下表面（$z = -t$，$t$ 为材料厚度），子面片原点在 $z = -t$，而子面片 STL 的上表面则位于其 link 坐标系中的 $z = t$，通过这种"上表面平齐 + 峰/谷分层"的策略，确保了展开状态时所有面片上表面平齐。

（2）**STL 网格生成**。对于每个面片，根据其二维顶点坐标在 $x$-$y$ 平面上生成多边形，然后沿 $z$ 方向拉伸材料厚度形成三维实体，输出为二进制格式的 STL 文件。面片的法线方向通过有向面积符号自动校正，确保所有三角面的法向外一致。

（3）**关节轴方向确定**。URDF 中每个旋转关节的旋转轴方向由折痕线的几何方向和峰/谷类型共同决定。具体方法为：计算子面片中心相对于折痕中点的偏移向量，在折痕法线方向上的投影符号决定了旋转轴的正方向；谷折关节的正转方向使得子面片向外打开，峰折关节则使得子面片向内折叠。这一方法保证了 URDF 模型中关节角度的符号与物理直觉一致。

### 3.2.6 MuJoCo 交互式仿真实现

仿真验证模块是整个平台的应用层核心。系统基于 DeepMind 的 MuJoCo 物理引擎搭建了交互式仿真环境（`MuJoCoSimulator`，定义于 `src/interactive/mujoco_simulator.py`），实现了从 URDF 到 MJCF（MuJoCo 的 XML 模型格式）的自动转换以及协同驱动的实时交互验证。

**URDF 到 MJCF 的转换。** 由于 MuJoCo 原生支持 MJCF 格式而非 URDF，系统在加载模型时自动将 URDF 转换为 MJCF XML 并进行增强。转换过程在 `_urdf_to_mjcf()` 方法中完成：首先解析 URDF 的关节树结构，重建 body 的层级关系；然后为每个关节添加 MJCF 格式的 hinge joint 定义，保留 URDF 中的运动范围（range）和旋转轴（axis）参数；同时添加视觉与场景元素——包括棋盘格纹理地面、亚克力/ABS 塑料质感的折纸手材质、以及三点照明（主光、补光和背光）以增强三维可视化效果。此外，在协同模式（synergy 模式）下，系统会创建额外的虚拟滑块（dummy slider）body，每个滑块对应一个协同控制输入，通过 `position actuator` 绑定到这些滑块上并提供 `kp=0`（不产生实际力矩）的占位驱动。

**协同驱动的实时验证。** 软件提供了四种可切换的协同驱动模式，用户无需修改代码即可灵活切换：

（1）**双滑块模式**：提供 Motor A 和 Motor B 两个滑块，使用增强自适应协同模型计算关节角。适用于基础协同行为验证。

（2）**四滑块互联动模式**：在双滑块基础上增加 $\sigma$（同动量）和 $\sigma_f$（差动量）两个滑块，且四个滑块之间互联动——拖动 A/B 滑块时自动计算并更新 $\sigma/\sigma_f$，反之亦然。这种设计使用户可以直观地理解协同输入的物理含义。

（3）**单侧协同模式**：引入松弛钳位机制，当某一驱动器输入为负值时，该侧缆绳被视为松弛（slack），不产生驱动力。在单马达激活时，系统直接使用从该马达出发的 Capstan 衰减传动矩阵 $R_A$ 或 $R_B$，确保关节响应沿路径单调衰减。该模式解决了原先线性模型中负马达值产生不合理负关节角和远端关节响应大于近端关节的问题。

（4）**动态协同模式**：增加一个 Speed 滑块（0-10 rad/s），根据用户设定的运动速度在慢速协同方向 $S_s$ 和快速协同方向 $S_f$ 之间平滑插值，实时展示速度对驱动模式的调制效应。慢速模式下系统近似于准静态增强协同，动态模式下阻尼效应占主导，关节响应更加集中。

仿真主循环中，每帧检测滑块值的变化，调用协同回调函数计算各关节的目标角度，通过 `mj_forward()` 前向运动学更新模型状态，并通过 `viewer.sync()` 同步到查看器显示。系统在退出时自动清理临时生成的 MJCF 文件。

### 3.2.7 优化设计框架

为辅助折纸手的结构参数优化设计，平台还集成了一个自动化优化框架（位于 `src/optimization/`）。该框架以协同模型的关节角预测值为基础，定义了若干目标函数（`objective_functions.py`）来评价设计的传动性能——例如手指弯曲角度范围、关节运动的协调性指标、以及摩擦非对称性利用效率等。优化引擎（`optimization_engine.py`）可与外部设计空间定义（`design_space.py`）配合，对滑轮位置、半径、摩擦系数等设计参数进行数值寻优。腱绳路径规划工具（`tendon_routing.py`）支持从设计空间中自动寻找可行的腱绳走线方案。这一框架为从手工设计到自动化优化的过渡提供了基础工具。
